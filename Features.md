# ✨ Features.md
> Multi-Category Marketplace — Complete Feature Set
> Architecture: Modular Monolith (FastAPI) + Next.js 15 frontend

---

## Module Map

Each feature maps to a specific backend module under `app/modules/` and a frontend folder under `components/`.

| Feature Area | Backend Module | Frontend Folder |
|---|---|---|
| Auth | `modules/auth/` | `components/auth/` |
| Products | `modules/products/` + `modules/categories/` | `components/product/` |
| Cart & Wishlist | `modules/cart/` + `modules/users/` | `components/cart/` |
| Checkout & Orders | `modules/orders/` | `components/checkout/` |
| Payments | `modules/payments/` | `components/checkout/PaymentStep` |
| Inventory | `modules/inventory/` | `components/vendor/InventoryTable` |
| Vendor | `modules/vendor/` | `components/vendor/` |
| AI Recommendations | `modules/recommendations/` | `components/product/RecommendationCarousel` |
| Analytics | `modules/analytics/` | `components/analytics/` |
| Reviews | `modules/reviews/` | `components/product/ReviewCard` |
| Emails | `workers/email_tasks.py` (ARQ) | — |
| Admin | `modules/admin/` | `components/admin/` |

## 1. Authentication & User Management
**Module:** `modules/auth/` + `modules/users/`

| Feature | Details |
|---|---|
| Register / Login | Email + password, JWT access (15m) + refresh (7d) tokens |
| OTP Verification | Email OTP via Resend — enqueued as ARQ background job |
| Forgot Password | Token-based reset link, email sent via ARQ worker |
| Profile Management | Name, avatar, phone, addresses (CRUD) |
| Role System | `customer`, `vendor`, `admin` — enforced via `core/dependencies.py` |
| Session Management | Refresh tokens stored in Redis, rotation on each refresh |
| Logout | Refresh token deleted from Redis — instant invalidation |
| Protected Routes | `middleware.ts` (Next.js) + `get_current_user` Depends (FastAPI) |

## 2. Product Catalog
**Module:** `modules/products/` + `modules/categories/`

| Feature | Details |
|---|---|
| Multi-Category | Hierarchical categories (parent → sub → child), tree API |
| Product Variants | Size, color, material — each variant has own price + stock |
| Rich Product Pages | Image gallery, description, specs, Q&A |
| Full-Text Search | MongoDB text index on title, description, tags |
| Filters | Category, price range, rating, brand, in-stock toggle |
| Sorting | Price ↑↓, popularity, newest, top-rated |
| SEO URLs | Slug-based `/products/nike-air-max-270-white` |
| Product Badges | Trending, New Arrival, Best Seller, On Sale |
| Image Upload | Multi-image Cloudinary upload via `utils/cloudinary_utils.py` |
| Slug Generation | Auto-generated via `utils/slug_utils.py`, unique-checked |

## 3. AI Product Recommendations
**Module:** `modules/recommendations/` → calls Claude Sonnet API, caches in Redis

| Feature | Details |
|---|---|
| Personalized Feed | Per-user homepage recommendations via Claude Sonnet |
| Similar Products | "You may also like" on product detail page |
| Trending Products | Globally popular products from `events` collection aggregation |
| Recently Viewed | Tracked via `POST /recommendations/event` (view events) |
| Context-Aware | Cart contents passed as context to AI prompt |
| Cold Start | Category-based picks for new users with no history |
| Redis Cache | Recommendations cached per user, TTL: 1 hour |
| Event Logging | All view / click / add-to-cart events stored in `events` collection |

## 4. Cart & Wishlist
**Module:** `modules/cart/` + `modules/users/`

| Feature | Details |
|---|---|
| Persistent Cart | Stored in MongoDB, synced to user on login |
| Guest Cart | Stored in localStorage, merged via `POST /cart/merge` on login |
| Add / Update / Remove | Full CRUD on cart items, per variant |
| Stock Validation | `POST /cart/validate` checks live inventory before checkout |
| Save for Later | Move items from cart to saved list |
| Wishlist | Add/remove products, stored in user document |
| Cart Summary | Subtotal, coupon discount, tax, shipping estimate |

## 5. Checkout & Orders
**Module:** `modules/orders/` — calls `inventory.service.deduct_stock()` on confirm

| Feature | Details |
|---|---|
| Multi-Step Checkout | Address → Shipping → Payment → Confirmation |
| Address Book | Saved addresses selectable at checkout |
| Coupon Codes | Flat, percentage, free-shipping types — validated in `cart.service` |
| Atomic Order Creation | Payment verify → create order → deduct stock (single transaction flow) |
| Order Status Timeline | Placed → Confirmed → Shipped → Delivered |
| Order History | Paginated, filterable by status and date |
| Invoice Download | PDF generated by `workers/pdf_tasks.py` (ARQ) |
| Return / Refund | Customer requests return → admin approves → Razorpay refund |
| Order Emails | Confirmation + shipping + delivery emails via ARQ `email_tasks.py` |

---

## 6. Payments
**Module:** `modules/payments/` → Razorpay SDK

| Feature | Details |
|---|---|
| Razorpay Checkout | Native modal: UPI, cards, net banking, wallets |
| Server-Side Order | Razorpay order created before modal opens (prevents tampering) |
| Signature Verification | HMAC-SHA256 in `payments.service.verify_payment_signature()` |
| Webhook Handler | Handles `payment.captured`, `payment.failed`, `refund.processed` |
| Refund | Partial and full refunds via admin panel |
| Transaction Log | All transactions saved to `transactions` collection |
| COD Support | Cash on Delivery as alternate at `PaymentStep` |

## 7. Inventory Management
**Module:** `modules/inventory/` — `deduct_stock()` called by `orders.service`

| Feature | Details |
|---|---|
| SKU Tracking | Unique SKU per product variant |
| Real-Time Stock | Quantity per variant, checked on add-to-cart and checkout |
| Low Stock Alerts | ARQ job `inventory_tasks.check_low_stock()` → Resend email |
| Auto-Deduction | Stock decremented atomically when order is confirmed |
| Vendor Restock | Vendor updates stock from dashboard |
| Out-of-Stock UI | Products marked OOS, add-to-cart CTA disabled |
| Audit Log | Every stock change logged to `inventory_logs` collection |
| Bulk CSV Import | `POST /inventory/bulk-update` parses CSV, batch updates |

## 11. Emails & Notifications
**Worker:** `workers/email_tasks.py` — all emails sent async via ARQ + Resend

| Trigger | Job Function |
|---|---|
| Registration | `send_otp_email()` |
| Order Placed | `send_order_confirmation()` |
| Order Shipped | `send_shipping_update()` |
| Order Delivered | `send_delivery_confirmation()` |
| Low Stock | `send_low_stock_alert()` — triggered by `inventory_tasks.py` |
| Refund Initiated | `send_refund_email()` |
| Vendor Payout | `send_payout_confirmation()` |
| Password Reset | `send_password_reset()` |

> All email jobs are **non-blocking** — FastAPI enqueues them and returns the response immediately. ARQ worker processes them in the background.
